# MiMo native MTP, depth one

Historical depth-one deployment; current depth-three support and measurements
are in [the MTP3 record](2026-09-22-mimo-mtp3.md).

Implementation for checkpoint `3b38d063180c3e4aed9691fdc735f3d10b266ee4`.
Native MTP executes `model.mtp.layers.0`; it does not recursively reuse this
block for deeper speculation or load the separate DFlash checkpoint.

The draft consumes the target's **post-final-norm** hidden state and the next
token embedding. Each is independently RMS-normalized, concatenated embedding
first, projected through replicated `eh_proj`, then passed through dense SWA
attention/MLP, draft final norm and the shared vocabulary head. QKV uses the
checkpoint's TP4 chunk/scale layout; attention and dense MLP are partitioned
across serving ranks. This follows the native SGLang/vLLM MiMo MTP contracts.

Verification uses two causal rows per request and DGPP's existing sampler and
grammar verification. Expanded sliding rings preserve the previous live window,
so rejected target tails are discarded by position. Draft caches have separate
rollback copies; prefix snapshots include the draft cache and hidden row.
The shared layer workspace includes the draft's dense SWA geometry, which is
larger than the backbone's dense global-attention layer.

## Validation

- Cross-build of serving binary, unit tests, layer probe and CUDA tests.
- 21 MiMo-filtered host tests pass (including native draft tensor placement).
- Nine MiMo CUDA test groups pass; CUDA memcheck reports zero errors.
- New CUDA differential test covers two verification rows per request,
  reordered slots, padding, repeated rejection/overwrite, ring wrap, and
  global attention's scalar/split transition at 512 keys.
- Real block-zero weights, independent CPU PyTorch oracle versus GPU probe:
  three rows give relative L2 errors 0.0034693, 0.0033919, 0.0056931; maximum
  absolute errors 0.125, 0.125, 0.25. All pass the existing 1% relative L2 / 5%
  peak-scaled error gate. Includes fusion and final norm, excludes vocabulary
  logits. This is layer evidence, not full-model HF equivalence.
- An older host test required rejecting a 129-slot sliding ring despite the
  existing expanded-ring implementation; it now tests capacity below window.

Matched greedy probes use 256 generated tokens, with one request followed by
two simultaneous requests. The two prompts ask for a Python interval-merging
function and an explanation of hash-table collisions/resizing. Client rate estimates divide 255 (the output budget minus one) by the
first nonempty streamed delta-to-completion interval, including streaming and
server snapshot overhead. Hidden special tokens can slightly affect these
absolute rate estimates; the elapsed-time speedup ratios do not depend on them. All four outputs are byte-identical with MTP off/on.

| Probe | MTP off tok/s | MTP on tok/s | Speedup |
|---|---:|---:|---:|
| Interval merging, alone | 23.93 | 34.92 | 1.46x |

| Interval merging, concurrent | 18.98 | 25.03 | 1.32x |

Concurrent rates are **per request**, not aggregate. This is a short local
comparison, not a claim about throughput at a full 256K context. The clean
baseline is `baseline-clean.json`; discard the earlier `baseline.json` timing
because GPU diagnostics overlapped it. MTP's first four probes accepted 478 of
544 drafts (87.9%) and exercised rejection, both batch sizes and two prefix
restores. Four snapshots of exactly 3,043,172,352 bytes were observed live.

The actual `ChatCompletionsClient -> RecordingTransport -> UrllibModelTransport`
harness replay passed six turns and **12/12 successful read-only repository
tool executions**, with the first request asserted equal to the user's recorded
payload. Additional streamed shell-command, typed read-file, and two-required-
argument write-file calls passed (generated shell/write operations were not
executed). These argument checks overlapped the latter harness turns to cover
concurrent constrained requests. All service requests completed without errors.
This validates tool transport/arguments, not a complete SWE-bench repair or
reasoning quality; later harness turns included lengthy repetitive reasoning.

free of errors; effective configuration digests and binary hashes match.
